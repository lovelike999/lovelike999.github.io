01
长视频输入与片段标准化
先把连续视频流转换为带稳定时间索引的 30 秒 clip
预切分 clip → 抽帧 + 提取音频；clip_id 同时作为后续文本节点的 temporal timestamp。
ffmpeg · 30 s / clip MoviePy · frame sampling fps = 5 audio = 16 kHz PCM WAV OpenCV · JPEG / Base64
ffmpeg / 30 s
固定片段时间单位，使 clip_id 能承担时间定位与前后文截断。
MoviePy / 5 FPS
解码视频并抽取 JPEG 帧，为后续人脸检测与 M3 多模态输入提供视觉证据。
16 kHz WAV
统一音频采样率，满足 Gemini 分轨与 ERes2NetV2 声纹模型的输入要求。
02
人物实体抽取：视觉与听觉并行
先形成稳定的 face / voice 节点，再交给 M3-Agent-Memorization
Face branch
InsightFace buffalo_l
RetinaFace 检测人脸框，ArcFace 输出 512-D 身份特征，用于人物节点构建。
det > 0.85 · quality > 22
最终质量门控，过滤误检、模糊脸和过小人脸，减少错误人物节点。
HDBSCAN ≥ 0.8 / 20 · cluster ≥ 20
先筛掉低质量样本，再把同一 clip 中重复出现的人脸归为稳定簇。
τimg ≥ 0.30 · max 10
跨 clip 做同人重识别；平均余弦达到阈值就复用 image node，并限制声纹/图存储规模。
top 3 / cluster · CPU
每个角色保留最多 3 张高质量代表脸；CPU 模式避免人脸检测占用 GPU。
Voice branch
Gemini 1.5 Pro-002
联合完成语音分轨与 ASR，给出每段开始时间、结束时间和字幕文本。
gap ≤ 0.6 s
合并同一说话人的相邻短句，避免一句话被切碎成多个 voice 片段。
min duration = 2 s
删除过短且声纹不稳定的语音，降低噪声与错误说话人聚类的概率。
ERes2NetV2 + FBank · 192-D
提取归一化声纹，用声音身份跨 clip 关联同一说话人。
τaudio ≥ 0.60 · max 20
平均余弦超过阈值就复用 voice node；限制 20 个向量控制存储和聚合成本。
pydub segmentation
按 Gemini 返回的时间边界提取真实音频段，供声纹模型计算。
输出可复用的稳定标识：<face_id> 与 <voice_id>，后续所有 memory 均通过这些实体 ID 连边。
03
M3-Agent-Memorization：生成 Episodic / Semantic Memory
输入包含当前 clip 视频、代表性人脸裁剪、带时间戳的语音文本和 memory prompt。模型同时输出 video_descriptions（原子事件）与 high_level_conclusions（高层推断、人物等价关系）。
Qwen2.5-Omni Thinker · 7B use_audio_in_video = True temperature = 1e−6 max_new_tokens = 4096 JSON schema constrained
M3-Agent-Memorization
同时阅读视频画面、人脸证据、语音文本和时间信息，生成 episodic / semantic memory。
use_audio_in_video = True
让模型在对齐视频时同步使用音轨，保留说话内容与画面事件的对应关系。
temperature = 1e−6
近似贪婪解码，减少随机性，使 memory 内容更稳定、便于复现。
max_new_tokens = 4096
为原子事件列表与高层结论预留足够长度，避免输出在中途被截断。
JSON schema
强制输出可解析的 video_descriptions 与 high_level_conclusions，直接进入建图。
04
文本向量化与多模态异构图写入
每条 memory 用 text-embedding-3-large 转为 3072-D 向量；正则提取实体标签后建立双向边。 Episodic 每条新建节点；Semantic 在实体子集一致时按相似度决定增强、削弱或新建。
nodes: img / voice / episodic / semantic sim > 0.85 → reinforce (+1) sim < 0 → weaken (−1) otherwise → new semantic node edge weight starts at 1.0
text-embedding-3-large · 3072-D
把原子事件和语义结论映射到统一向量空间，支持后续余弦检索。
entity regex <…>
识别人名、人脸和语音 ID，把文本节点连接到对应人物实体。
Episodic → new node
保留每个 clip 的独立事件与时间顺序，便于按时间或事件回溯。
Semantic sim > 0.85
视为重复或高度一致的结论，增强已有节点连边而不重复添加。
Semantic sim < 0
视为冲突信号，削弱已有连接；当前实现不会再为冲突结论新建节点。
otherwise → new semantic node
保留新知识；双向边初始权重为 1，后续通过增强/削弱累积证据。
05
人物身份合并与持久化
扫描 “Equivalence: <face_x>, <voice_y>” 语义节点，用并查集将 face / voice 合并为 character_k；最后执行 refresh_equivalences()，将完整 VideoGraph 序列化为 pickle。
union-find character_mappings reverse_character_mappings *.pkl + temporal clip index
Equivalence semantic nodes
提供 face 与 voice 属于同一人物的显式证据，作为身份合并输入。
Union-find
处理多个等价关系的传递合并，把多个 face/voice ID 归并为一个 character。
refresh_equivalences()
重新计算正反向人物映射，保证节点、检索和回答使用一致的人物身份。
pickle (*.pkl)
持久化节点、边、向量和角色映射；在线问答时直接加载，避免重复生成。
τ
Threshold quick reference
clip = 30 s · 定义时间索引与检索粒度
fps = 5 · 平衡动作覆盖与视觉计算成本
face ≥ 0.85 / 22 · 保证人脸检测和质量可靠
face match ≥ 0.30 · 跨片段确认同一人物
voice ≥ 2 s · 排除过短、不可靠的语音
voice match ≥ 0.60 · 跨片段关联同一说话人
semantic > 0.85 · 合并重复结论并增强边
semantic < 0 · 削弱相互冲突的证据
text dim = 3072 · 提供高容量语义检索空间
temperature = 1e−6 · 降低生成随机性并提高复现性
